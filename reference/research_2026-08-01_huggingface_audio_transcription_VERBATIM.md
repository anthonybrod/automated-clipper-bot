### Important correction to the premise, verified via faster-whisper's own source (github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/vad.py)

Your `vad_filter` parameter in faster-whisper **already is Silero VAD** — the library bundles `silero_vad_v6.onnx` internally and runs it via onnxruntime on CPU before decoding. So "VAD alternatives on Hugging Face" is close to a non-question for your current setup: you're not searching for an upgrade to something homemade, you're already running the industry-standard lightweight VAD under the hood. The only thing genuinely worth comparing it against is **pyannote/segmentation-3.0** (row 10) — heavier, gated, but adds overlapped-speech detection (useful only if you also adopt diarization, since VAD alone gives you nothing segmentation-3.0 doesn't already fold into the diarization pipeline).

### What's genuinely worth considering

- **distil-whisper/distil-large-v3** (row 4) — the strongest actual finding of this pass. 6.3x faster than large-v3, within ~0.2% WER on real benchmarks, and its own model card documents faster-whisper/CTranslate2 compatibility with working code. This is a legitimate speed upgrade to evaluate against your current large-v3/turbo choice, not just a name-alike.
- **deepdml/faster-whisper-large-v3-turbo-ct2** (row 2) — same story, drop-in CT2 weights for the turbo variant, zero code changes to try.
- **MIT/ast-finetuned-audioset-10-10-0.4593** (row 11) or its lighter PANNs cousin (row 12) — the one real, concrete answer to "detect screaming/shouting/laughing from raw audio." Verified against the actual AudioSet ontology that Screaming, Shout, Yell, and Laughter are real, distinct classes these models can output probabilities for. This is a legitimate complement to your RMS-spike detector: RMS tells you *something* loud happened, AST/PANNs tells you *it was a scream* (vs. a bass drop or gunshot sound effect).
- **pyannote/speaker-diarization-community-1** (row 9) — if you ever add diarization to separate streamer voice from co-host/game audio, this beats 3.1 on DER, though note the license moved to CC-BY-4.0.

### What sounds relevant but isn't, or has a real catch

- **FunAudioLLM/SenseVoiceSmall** (row 13) — by name and description this looks like the exact "emotion + event detection" tool you want, but its own card only lists laughter/crying/applause/coughing/sneezing as detectable events — **no screaming or shouting class**. Combined with an ambiguous custom license, this is a "sounds right, isn't" case worth flagging explicitly, same pattern as the CanadianZombies/download-twitch mismatch from earlier research.
- **usefulsensors/moonshine** (row 6) — optimized for cheap edge hardware, not for accuracy on messy gaming audio; its own card admits hallucination/repetition problems and provides no real WER comparison despite claiming superiority.
- **audeering/wav2vec2-large-robust-12-ft-emotion-msp-dim** (row 17) — the most technically elegant fit for a continuous "excitement" signal, but is explicitly research-only; using it in a monetized clip pipeline would require buying a commercial license from audEERING.
- **Silero VAD on Hugging Face** (row 18) — not a real independent HF finding; it's already inside faster-whisper, and the HF listings for it are just unofficial low-traffic mirrors of a GitHub/PyPI project.
- **Kyutai STT** (row 7) — genuinely good streaming tech, but architecturally aimed at live conversational latency, not the buffered/batched clip-review workflow this project uses; low current adoption (135 likes) makes it a riskier bet than the Whisper-ecosystem options.
- **ehcalabres and firdhokk emotion models** (rows 14–15) — real, working, reasonably popular, but both trained exclusively on small acted-emotion datasets (RAVDESS/SAVEE/TESS/URDU — actors reading scripted lines), so their real-world accuracy on spontaneous, noisy Twitch reactions is unverified and should be tested before being trusted for automated clip selection.
